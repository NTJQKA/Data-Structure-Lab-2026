# Simple Calculator

2026 年数据结构实验课第一次实验：**A Simple Calculator**。

本项目使用 C++ 实现表达式求值，旨在练习栈的逻辑结构、存储结构和基本操作，以及运算符优先级在表达式计算中的应用。

> 当前项目已实现主要计算逻辑，并接入表达式语法检查：检查通过后才进行分词和双栈求值。现有入口支持读取一行表达式，完整 UI、数学异常处理及系统的软件测试仍待完善。

## 实验目标

- 掌握栈的入栈、出栈、访问栈顶等基本操作。
- 使用操作数栈和运算符栈处理表达式，理解栈内、栈外优先级的作用。
- 熟悉 C++ 程序的编辑、编译、链接、运行与调试过程。

## 功能要求

1. 提供友好的用户界面及简单的使用说明。
2. 从键盘读取表达式，以 `=` 作为结束标记。
3. 支持整数、小数、括号，以及以下运算。
4. 计算表达式并输出结果，对非法输入给出提示。

| 符号 | 运算或作用 |
| --- | --- |
| `+`、`-` | 加、减 |
| `*`、`/` | 乘、除 |
| `%` | 求模 |
| `^` | 乘方 |
| `&` | 开方 |
| `(`、`)` | 改变运算顺序 |
| `=` | 表达式结束标记 |

示例表达式如下，括号统一写为英文半角形式：

```text
-2*3^5 + 23/(45+67) - 17%3/8&2 =
```

这里的 `^` 和 `&` 是计算器表达式中定义的乘方、开方符号。当前 `calculate()` 使用 `pow(x, y)` 计算 `x^y`，使用 `pow(x, 1 / y)` 计算 `x&y`（对 `x` 开 `y` 次方）。

## 实现思路

使用两个栈分别保存操作数和运算符：

- **操作数栈 `sta_x`**：保存读入的数值及中间计算结果，对应课件中的 `opnd`。
- **运算符栈 `sta_op`**：保存尚未完成计算的运算符，对应课件中的 `optr`。

`main.cpp` 先读取一行原始表达式，再调用 `Correction.cpp` 中的 `check()`。该函数检查数字格式、括号匹配、操作数和运算符的位置，以及末尾的 `=`；失败时输出错误位置和原因，主程序立即退出，不进入分词与求值。它只检查语法，不会自动修改输入，也不负责判断除零等数学错误。

检查通过后，`tokenizer()` 将表达式拆分为数字和符号，`tool()` 再处理表达式开头及左括号后的负号。`solve()` 从空栈开始依次读取这些 Token。遇到数字时，将其压入操作数栈；遇到运算符时，如果运算符栈非空，则比较栈顶运算符的栈内优先级与当前运算符的栈外优先级：

1. **栈为空或栈内优先级较低**：当前运算符入栈，继续读取下一个符号。
2. **栈内优先级较高**：弹出一个运算符和两个操作数进行计算，将结果入栈，然后继续处理当前运算符。注意先弹出的是右操作数。
3. **优先级相等**：弹出栈顶运算符，用于匹配左右括号。

末尾的 `=` 触发剩余运算。对于符合要求的表达式，最终操作数栈中只剩一个结果，运算符栈中留下 `=`。表达式完整性由入口的语法检查负责，求值器内部的防御性栈状态检查仍可进一步完善。

### 优先级表

现有代码中的 `lev_in`、`lev_out` 也按课件中优先级定义。数值越大，优先级越高。

| 运算符 | 栈内优先级 | 栈外优先级 |
| --- | ---: | ---: |
| `=` | 0 | 0 |
| `+`、`-` | 3 | 2 |
| `*`、`/`、`%` | 5 | 4 |
| `(` | 1 | 8 |
| `)` | 8 | 1 |
| `^`、`&` | 7 | 6 |

当前代码使用标准库的 `std::stack` 完成求值。

### 当前限制

- 请使用英文半角符号，表达式末尾需要 `=`，不可空格拆开一个完整的数。
- 一元负号仅允许出现在表达式开头或左括号后，例如 `-2=`、`2*(-3)=`；当前不支持一元正号及 `2*-3=` 这种写法。
- 小数点前后必须有数字，例如使用 `0.5`，不能写成 `.5` 或 `1.`。
- 语法检查通过不代表数学运算一定有定义。直接调用求值模块时，也应先调用 `check()` 检查输入。
- `%` 当前先将两侧操作数转换为 `int` 再求余，非整数输入的处理规则有待完善。
- 乘方、开方运算后会检查结果是否为有限数；无定义或超出 `double` 可表示范围时，程序会给出错误提示。

## 编译与运行

代码使用 C++17 的结构化绑定及标准库头文件。以下以 GCC / MinGW-w64 为例。

在仓库根目录打开 PowerShell，编译并运行主程序：

```powershell
cd simple-calculator
g++ -std=c++17 -Wall -Wextra main.cpp Calculator.cpp Correction.cpp -o Calculator.exe
.\Calculator.exe
```

三个 `.cpp` 文件分别编译并链接为一个程序，头文件无需单独编译，也不要直接包含 `.cpp` 文件。`main.cpp` 是应用程序的唯一入口。`tests/` 和 `experiments/` 不与应用程序一起链接。

运行后输入表达式并回车，例如：

```text
-2*3^5+23/(45+67)-17%3/8&2=
```

语法检查通过后，程序先输出处理后的分词序列，再输出计算结果：

```text
0 - 2 * 3 ^ 5 + 23 / ( 45 + 67 ) - 17 % 3 / 8 & 2 =
-486.502
```

结果使用默认输出精度，显示值经过舍入。输入 `1+=` 等非法表达式时，程序输出语法错误提示并跳过本次分词与求值；随后询问是否继续计算。输入 Y 或 y 可继续输入下一条表达式，其他字符则结束程序

### 语法检查回归测试

在 `simple-calculator` 目录中运行：

```powershell
New-Item -ItemType Directory -Force build | Out-Null
g++ -std=c++17 -Wall -Wextra tests/CorrectionTests.cpp Correction.cpp -o build/CorrectionTests.exe
.\build\CorrectionTests.exe
```

测试覆盖合法表达式、负号、小数、空白、括号错误、缺少操作数或运算符、错误结束标记、非法字符和超范围数字。
`1/0=` 被视为语法正确，除零问题由求值阶段处理。

### 手动测试

在 Windows 环境下进行键盘输入测试，测试数据、运行截图及修复后结果记录于《（测试）实验用表达式(1).docx》。

- **课程表达式**：已测试简单、中等复杂、复杂及非法表达式。平方写为 `^2`，`sqrt(...)` 转为 `((...)&2)` 的等价形式，并补齐末尾 `=`。
- **补充测试通过**：运算优先级、负号与括号、连续乘方按课件左结合求值、小数格式、空格、缺少操作数、空括号和结束标记处理符合预期；除数、模数在计算中变为零时能够提示错误。
- **连续计算通过**：分别在除零、模数为零及语法错误后继续输入合法表达式，得到正确结果，验证错误后状态清理。
- **修复后复测通过**：`12.4^3=` 显示 `1906.624`；缩小近零判断阈值后，`2/0.0000000002=` 得到 `10000000000`；`(-27)&3=` 得到 `-3`，`(-16)&2=`、`5&0=` 分别提示负数不能开偶次方根、零次方根无定义。
以上结论仅覆盖记录中的用例，不代表所有数值边界和交互场景均已验证。
